# 后端 API 协作手册

本文面向前端、测试与 AI Engine 协作同学，描述当前后端 MVP 的联调方式和 HTTP 契约。更完整的设计背景见 [Spec C 后端设计](./backend-design.md)，精确字段定义以 [shared/schemas.py](../shared/schemas.py) 为准。

## 当前状态

- 分支：`CJN/backend-mvp`
- 后端框架：FastAPI
- API 前缀：`/api`
- 鉴权方式：用户名密码登录后写入 `session_id` httpOnly Cookie
- 数据库：SQLite，默认路径 `data/questions.db`
- 向量库：ChromaDB，默认路径 `data/chroma`，集合 `questions`
- 真实题库：后端按 ingestion 当前 schema 读取 `questions`、`knowledge_points`、`question_knowledge_points`；readiness 会同时校验 SQLite 题库和 Chroma 向量库；`difficulty` 字段已从题库契约中移除
- 当前 AI Engine：开发/生产环境走 Parser → Retriever → Reviser 真实链路；`BACKEND_ENV=test` 使用确定性 fixture，供前端和自动化测试在无 API key 时联调
- Swagger UI：后端启动后访问 `http://127.0.0.1:8000/docs`

## 鉴权约定

除以下接口外，所有业务接口都要求已登录：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/health`
- `/docs`、`/openapi.json`

登录成功后，后端返回用户信息并设置 Cookie：

```http
Set-Cookie: session_id=...; HttpOnly; Path=/; SameSite=Lax
```

前端请求必须带上 Cookie。浏览器同源部署时自动携带；开发期如跨源请求，需要 `credentials: "include"`。

## 统一错误体

所有后端业务错误统一返回：

```json
{
  "error_code": "auth.unauthorized",
  "message": "未登录或会话已过期",
  "detail": null,
  "trace_id": "..."
}
```

前端应优先根据 `error_code` 分派交互，不要解析 `message`。

常用错误码：

| error_code | HTTP | 含义 | 前端建议 |
|---|---:|---|---|
| `auth.unauthorized` | 401 | 未登录或 session 过期 | 跳登录页 |
| `auth.invalid_credentials` | 401 | 用户名或密码错误 | 表单错误提示 |
| `auth.username_conflict` | 409 | 用户名重复 | 表单错误提示 |
| `resource.not_found` | 404 | 资源不存在或无权访问 | toast 或回列表 |
| `request.invalid` | 422 | 请求体校验失败 | 表单/开发错误提示 |
| `rate.exceeded` | 429 | 触发软限流 | 稍后重试 |
| `ai.parser_failed` | 400 | AI 无法理解生成需求 | 让用户改写需求 |
| `ai.no_candidate` | 422 | 题库无候选题 | 让用户放宽条件 |
| `ai.llm_upstream` | 502 | LLM 上游异常 | 稍后重试 |
| `server.internal` | 500 | 未预期错误 | 展示通用错误并记录 trace_id |

## 接口总览

| 方法 | 路径 | 鉴权 | 请求体 | 响应体 |
|---|---|---|---|---|
| GET | `/api/health` | 否 | 无 | `{ "status": "ok" }` |
| GET | `/api/health/ready` | 否 | 无 | readiness checks |
| POST | `/api/auth/register` | 否 | `UserCredentials` | `User` |
| POST | `/api/auth/login` | 否 | `UserCredentials` | `User` |
| POST | `/api/auth/logout` | 是 | 无 | 204 |
| GET | `/api/auth/me` | 是 | 无 | `User` |
| POST | `/api/papers/generate` | 是 | `GeneratePaperRequest` | `Paper` |
| POST | `/api/papers/revise` | 是 | `RevisePaperRequest` | `Paper` |
| GET | `/api/papers` | 是 | query: `limit`, `offset` | `PaperListResponse` |
| GET | `/api/papers/{paper_id}` | 是 | 无 | `Paper` |
| POST | `/api/solutions` | 是 | `SolutionRequest` | `SolutionResponse` |
| POST | `/api/attempts` | 是 | `GradeSubmissionRequest` | `GradeSubmissionResponse` |
| GET | `/api/users/me/mastery` | 是 | query: `window_days` | `MasteryProfile` |

## 健康检查

`GET /api/health` 是轻量存活检查，只返回：

```json
{ "status": "ok" }
```

`GET /api/health/ready` 是 readiness 检查，会验证 SQLite 可连接、后端关键表存在、题库 schema 可读、Chroma collection `questions` 可读，且 Chroma 向量数与 SQLite 题量一致。全部通过返回 200：

```json
{
  "status": "ready",
  "checks": {
    "sqlite": true,
    "core_tables": true,
    "question_bank": true,
    "vector_bank": true
  }
}
```

任一检查失败返回 503，`status` 为 `not_ready`，`checks` 中标出失败项。

## 数据模型速查

### UserCredentials

```json
{
  "username": "demo",
  "password": "demo123"
}
```

约束：

- `username`：3-32 位，只允许英文字母、数字、下划线
- `password`：6-128 位

### User

```json
{
  "id": "uuid_hex",
  "username": "demo",
  "created_at": "2026-07-09T10:00:00Z"
}
```

### GeneratePaperRequest

```json
{
  "user_query": "来 3 道现在完成时选择题，中等难度",
  "mode": "fresh",
  "wrong_items": null,
  "review_window_days": null
}
```

`mode` 可选：

- `fresh`：按自然语言生成新试卷
- `remediation`：基于错题巩固，通常传 `wrong_items`
- `review`：基于历史掌握度复习，可传 `review_window_days`

### Paper

`Paper` 是完整试卷，关键字段：

```json
{
  "paper_id": "uuid_hex",
  "title": "来 3 道现在完成时选择题 - 英语练习",
  "generated_at": "2026-07-09T10:00:00Z",
  "request": {},
  "items": [
    {
      "index": 1,
      "score": 5,
      "source_question_id": "fake_q_0001",
      "revision_mode": "fresh",
      "revision_notes": "Generated by deterministic fake engine.",
      "question": {
        "stem": "Choose the correct answer for question 1.",
        "question_type": "single_choice",
        "options": [
          { "label": "A", "text": "go" },
          { "label": "B", "text": "goes" },
          { "label": "C", "text": "went" },
          { "label": "D", "text": "gone" }
        ],
        "answer": "B",
        "solution": null,
        "knowledge_point_ids": ["kp_single_choice_basic"]
      }
    }
  ],
  "total_score": 15,
  "metadata": {}
}
```

`metadata` 由 AI Engine 生成并由后端原样持久化、返回。前端不得依赖未知字段；当前稳定的调试字段包括 `stage_ms`（parser/retriever/reviser/total 的耗时）、`vector_retrieval`、`retrieval_warnings`、`retrieval_shortfall`。这些字段适合开发面板，不应阻塞正常做题流程。

前端渲染做题页主要用 `items[].question`、`items[].score`、`paper_id`。提交答案时只需要回传题号和用户答案。

`question.answer` 与真实题库 `answer_json` 对齐，有两种形态：

```json
"B"
```

```json
[
  { "blank1": ["in"], "blank2": ["order"] },
  { "blank1": ["so"], "blank2": ["as"] }
]
```

单选题是单字母字符串；词性转换和句子改写是候选组合列表。外层列表表示多种可接受填法，每个 `blankN` 的数组表示该空的同义候选。

### PaperListResponse

列表接口不会返回完整题面：

```json
{
  "items": [
    {
      "paper_id": "uuid_hex",
      "title": "英语练习",
      "generated_at": "2026-07-09T10:00:00Z",
      "total_questions": 3,
      "total_score": 15,
      "submitted": false
    }
  ]
}
```

### GradeSubmissionRequest

```json
{
  "paper_id": "uuid_hex",
  "items": [
    { "index": 1, "user_answer": "B" },
    { "index": 2, "user_answer": "written" },
    { "index": 3, "user_answer": ["so", "that"] }
  ]
}
```

`user_answer` 支持三种提交形态：

```json
"written"
```

```json
["so", "that"]
```

```json
{ "blank1": "so", "blank2": "that" }
```

单空题可以直接提交字符串；多空题推荐前端提交 `blankN` 字典，数组也可按空位顺序提交。

### GradeSubmissionResponse

```json
{
  "attempt_id": "uuid_hex",
  "items": [
    {
      "index": 1,
      "user_answer": "B",
      "correct_answer": "B",
      "is_correct": true
    }
  ]
}
```

判分规则：

- `single_choice`：去首尾空白后转大写比较，如 `b` 等于 `B`
- `word_form` / `sentence_rewriting`：把用户答案归一化为 `blankN`，再检查是否命中 `answer` 中任一候选组合
- 归一化：小写、trim、折叠多空白、忽略末尾 `. ! ? , ; :`
- 判分永远不调用 LLM

### SolutionRequest

```json
{
  "question": {
    "stem": "Choose the correct answer for question 1.",
    "question_type": "single_choice",
    "options": [
      { "label": "A", "text": "go" },
      { "label": "B", "text": "goes" },
      { "label": "C", "text": "went" },
      { "label": "D", "text": "gone" }
    ],
    "answer": "B",
    "solution": null,
    "knowledge_point_ids": ["kp_single_choice_basic"]
  },
  "source_question_id": "fake_q_0001",
  "revision_mode": "fresh"
}
```

响应：

```json
{
  "solution": "答案是 B。题型为 single_choice，按题干要求作答即可。"
}
```

### MasteryProfile

```json
{
  "user_id": "uuid_hex",
  "window_days": null,
  "weak_kps": [
    {
      "knowledge_point_id": "kp_word_form_participle",
      "attempts": 3,
      "correct_rate": 0.3333333333,
      "mastery": 0.0615
    }
  ],
  "dominant_types": ["word_form"],
  "total_attempts_considered": 9
}
```

`mastery` 使用 Wilson lower bound，数值越低表示越薄弱。

## 典型联调流程

### 1. 注册或登录

```bash
curl -i -X POST http://127.0.0.1:8000/api/auth/register ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"demo\",\"password\":\"demo123\"}"
```

浏览器前端不需要手动读 `session_id`，只要后续请求携带 Cookie 即可。

### 2. 生成试卷

```bash
curl -X POST http://127.0.0.1:8000/api/papers/generate ^
  -H "Content-Type: application/json" ^
  -b "session_id=<从登录响应获取>" ^
  -d "{\"user_query\":\"来 3 道中等难度英语题\",\"mode\":\"fresh\"}"
```

保存响应里的 `paper_id`。

### 3. 提交答案

```bash
curl -X POST http://127.0.0.1:8000/api/attempts ^
  -H "Content-Type: application/json" ^
  -b "session_id=<从登录响应获取>" ^
  -d "{\"paper_id\":\"<paper_id>\",\"items\":[{\"index\":1,\"user_answer\":\"B\"},{\"index\":2,\"user_answer\":\"written\"},{\"index\":3,\"user_answer\":{\"blank1\":\"so\",\"blank2\":\"that\"}}]}"
```

同一份试卷允许重复提交，每次都会生成新的 `attempt_id`。

### 4. 查看掌握度

```bash
curl -b "session_id=<从登录响应获取>" ^
  http://127.0.0.1:8000/api/users/me/mastery
```

## Fake AI Engine 行为

当前 `ai_engine/` 是后端联调用的确定性实现：

- `user_query` 中出现数字，会作为题目数量，范围限制为 1-20
- 包含“选择”或 `choice` 时生成单选题
- 包含“词”或 `word` 时生成词形转换题
- 包含“改写”或 `rewrite` 时生成句子改写题
- 未指定题型时按三种题型轮换
- 题目不再带 `difficulty`
- 词性转换和句子改写会返回 `answer_json` 风格的多空候选结构

这让前端和测试可以稳定复现主链路。接入真实 AI Engine 时，HTTP 契约不应变化，只替换 `ai_engine` 内部实现。

## 测试专用接口

仅当 `BACKEND_ENV=test` 时挂载：

- `GET /api/test/db-inspect?table=papers`
- `POST /api/test/llm-scripts`

开发/生产环境不会注册这些路由。前端业务代码不要依赖 `/api/test/*`。

## 协作边界

### 前端

- 只通过 `/api/*` 调后端，不直接访问 SQLite 或 AI Engine
- 登录态交给 Cookie，不在 localStorage 保存 token
- 出错时按 `error_code` 分派
- 试卷列表页使用 `GET /api/papers`，进入详情时再调用 `GET /api/papers/{paper_id}`

### 后端

- 所有受保护接口都从 session 注入 `user_id`
- `paper_id + user_id` 一起校验资源归属；用户 A 访问用户 B 试卷返回 404
- 判分只在 `POST /api/attempts` 内部执行
- 保存完整 `Paper` JSON，列表只返回摘要
- 题库读取统一走 `shared/storage.py`，不要在业务模块里散落手写 SQL

### AI Engine

- 只暴露函数级契约，不感知 HTTP
- 不处理鉴权、不写 `papers` 表、不判分
- `revise_paper` 返回新 `paper_id`

### 测试

- 后端集成测试使用 FastAPI TestClient + 临时 SQLite
- 不依赖真实 LLM
- 关键用例在 `tests/integration/backend/` 中，可作为调用示例参考

## 破坏性变更规则

以下改动需要提前通知前端和测试同学，并同步更新本文：

- 修改任一请求体或响应体字段名
- 修改 `error_code`
- 修改 Cookie 名称 `session_id`
- 修改列表接口是否返回完整题面
- 修改判分规则
- 修改 `/api` 前缀或路由路径
- 修改 fake AI Engine 的稳定输出规则
